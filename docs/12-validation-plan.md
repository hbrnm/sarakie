# 12 — Model Validation Plan

ROI is reported but is **never** the primary validation criterion: it is high-variance and path-dependent.

## 1. Data and leakage control

- Every prediction is generated by `analyzeFixture(fixture, { asOf })` with `asOf` = a fixed time before kickoff (e.g. kickoff − 24 h, `PROVISIONAL`).
- Inputs are only matches with `kickoff_utc < asOf`, and only odds with `captured_at ≤ asOf` (or source timestamp ≤ asOf for historical odds datasets).
- Season-level aggregates such as final tables and full-season averages are forbidden.
- A leakage test suite perturbs future data and asserts the outputs are unchanged.

## 2. Chronological design

- **Walk-forward (expanding window):** fit on all data before matchday `m`, predict matchday `m`, then advance.
- **Tuning / test split:** hyper-parameters (`k`, `N_team`, thresholds) are tuned on seasons S₁…Sₙ₋₁ and reported once on the untouched season Sₙ. The test season is never used for tuning.
- Minimum: 2 tuning seasons + 1 test season per league, subject to data availability (S-04/S-50).

## 3. Metrics

| Metric | Applies to | Notes |
|---|---|---|
| Log loss | 1X2 (3-class), binary markets | Primary metric for tuning |
| Multiclass Brier score | 1X2 | `Σ_k (p_k − y_k)²` averaged |
| Brier score | O/U lines, BTTS, DC, DNB (excluding pushes) | |
| Calibration bins / reliability diagram | all markets | 10 equal-count bins; observed frequency with 95% Wilson CI per bin |
| Calibration slope/intercept | binary markets | logistic recalibration fit, reported only |
| Sample sizes | everything | Every metric is reported with `n` |
| Segmentation | league × market | Also by season phase (early: matchdays 1–8 vs rest) |

## 4. Benchmarks

1. **Market benchmark:** de-vigged closing (or latest pre-`asOf`) probabilities from the same markets. The model is compared on log loss and Brier score. The model is not expected to beat the market overall; the question is where it disagrees and whether those disagreements are informative.
2. **Naive benchmarks:** league base rates (home/draw/away frequencies, over-rates) and a strengths-off model (`α = δ = 1`).
3. **Closing-line value (CLV):** for `QUALIFIED`/`WATCHLIST` selections, compare the taken price with the closing price, `CLV = odds_taken / odds_close − 1`, and compare the de-vigged closing probability with `p_model`. Only where reliable closing odds exist (candidate source S-50).

## 5. Paper-tracking (live, Phase 5+)

- Notional 1 unit per `QUALIFIED` selection; settled in `prediction_outcomes`.
- Report the number of selections, hit rate vs. mean predicted probability, ROI with a bootstrap 95% CI, and mean CLV.
- No conclusions are drawn on fewer than a pre-registered minimum (PROVISIONAL: 300 settled selections per market group). Below that, results are labelled "insufficient sample".

## 6. Decision rules for Phase 6 outcomes

| Observation | Action |
|---|---|
| Model log loss worse than naive base rates | Model is not fit for use. Stop `QUALIFIED` output and revisit the specification |
| Systematic draw underestimation in calibration | Evaluate Dixon-Coles (requires PO approval) |
| Calibrated but no CLV | Keep as a research tool; tighten thresholds |
| Positive CLV over sufficient sample with good calibration | Continue paper tracking; consider threshold refinement |
